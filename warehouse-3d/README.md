# Склад 3D

Визуализация складов для **мониторинга и контроля**: рисуем склад от формы помещений до ячеек с размерами
**Ш × Г × В** (ширина, глубина, высота) и показываем на 3D, планах, картах стеллажей и графиках,
что лежит в ячейках, насколько они заполнены и где нарушены правила хранения.

Оперативный учёт (приход, выдача, перемещения, документы) ведёт учётная система — 1С, ERP или WMS.
Приложение получает от неё **срез остатков по адресам ячеек** и ничего в учёте не меняет.
Объектов (складов) может быть сколько угодно: склады с этажами и мезонинами, дворовые территории, навесы,
производственные кладовые и виртуальные склады (например, IT-техника по сотрудникам и кабинетам).

## Разделы

| Раздел          | Что показывает                                                                                                                                                                                         |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Обзор**       | дашборд одного из уровней: **Склады / Помещения / Ячейки** — заполнение, места, нагрузка, нарушения, 3D-карта с выносками                                                                              |
| **Ячейки**      | дерево «склад → помещение → зона → стеллаж», фасад стеллажа (ярусы × секции), карточка ячейки: размеры, тип, места, нагрузка, содержимое по партиям                                                    |
| **ТМЦ**         | где лежит каждая позиция: ячейки, партии, плавки и сертификаты, сроки годности, заказы для полуфабрикатов и готовых изделий                                                                            |
| **Тара**        | поддоны, ящики, барабаны, кассеты и **газовые баллоны**: полные и пустые на складе, у кладовых производства, у поставщиков                                                                             |
| **Контроль**    | нарушения правил хранения по уровням важности со ссылкой на ячейку на 3D                                                                                                                               |
| **Аналитика**   | графики: заполнение во времени и по помещениям, груз на хранении, типы ячеек, распределение заполнения, нагрузка стеллажей, движения и ABC-обращаемость ячеек, выдача на кладовые, ячейки без движения |
| **Конструктор** | здания и этажи, зоны, стеллажи, мезонины, ячейки, техника; для виртуального склада — места учёта                                                                                                       |
| **Настройки**   | объекты, подключение к учётной системе и сопоставление полей, кладовые производства, виды тары, тема                                                                                                   |

### 3D-карта

- Мультяшный стиль: пол с разметкой, тени, грузы по видам хранения — паллеты, короба, штучный инструмент
  на полках, листы и трубы металлопроката, барабаны кабеля, бочки ЛКМ, баллоны по цвету газа.
- Понимание высоты: слой «Высоты» (отметки ярусов и настилов, предел высоты зоны размещения) и срез по отметке —
  всё выше неё скрывается, видны нижние ярусы, уровни мезонина, нижний этаж.
- Этажность: этажи раздвигаются по вертикали или показываются по одному; мезонины с лестницами и ограждением.
- Стены «как в кукольном доме»: ближние к камере срезаны, дальние целые; режимы «срез / полные / скрыть».
- Окраска: как есть, заполнение, нагрузка, группы ТМЦ, контроль, давность движения; фильтр
  «свободные / частично / полные / с нарушениями».
- Наведение показывает карточку ячейки, щелчок — открывает её; виды: изометрия, сверху, спереди, по объекту.

### Модель склада

- **Помещения**: складское, дворовая территория, навес, производственное, офис, техническое; любая форма контура
  (прямоугольник, Г-, П-, Т-образное или по точкам), этаж и отметка пола.
- **Зоны**: стеллажное и напольное хранение, приёмка, отгрузка, **выдача на кладовые производства**, буфер,
  ЛВЖ / опасные грузы, тара, карантин; **предельная высота размещения**, допустимые группы ТМЦ.
- **Стеллажи**: паллетные, полочные, консольные (металлопрокат), напольное хранение, баллонные.
  У каждого стеллажа своя **нагрузка**: на стеллаж, на секцию и на ячейку (по ярусам).
- **Ячейки**: паллетная, коробочная, полочная (штучная), консольная, напольная (штабель), баллонная;
  число мест считается по размерам или задаётся вручную; блокировка, закрепление за кладовой.
- **Группы ТМЦ**: металлопрокат, сварочные материалы, ЛКМ, технические газы, арматура, метизы, кабель,
  электротехника, инструмент, расходники, СИЗ, запчасти, оборудование, химия и ГСМ, IT, **полуфабрикаты**,
  **готовые изделия**. Для каждой — вид хранения (паллета, короб, штучно, длинномер, штабель, баллоны) и единицы.
- **Тара**: поддоны EUR и FIN, короба, ящики, бочки, кабельные барабаны, кассеты для длинномера, мешки МКР,
  баллоны кислородные, пропан-бутан, аргоновые, со сварочной смесью, углекислотные, ацетиленовые.

### Правила контроля

Критичные: товар в заблокированной ячейке, перегруз ячейки, секции или стеллажа, ЛВЖ или газ вне зоны ЛВЖ,
**кислород вместе с горючими газами**, истёкший срок годности.
Предупреждения: мест занято больше, чем есть; тип ячейки не подходит товару; разные товары в моно-ячейке;
обычный товар в зоне ЛВЖ; ТМЦ не по назначению зоны; срок годности истекает в 30 дней.
Информация: нет движения больше 90 дней.

## Данные из учётной системы

**Настройки → Учётная система**:

- _REST API_ — опрос среза (JSON или CSV) с заданным интервалом;
- _WebSocket_ — изменения по ячейкам в реальном времени (частичный срез);
- _Файл_ — выгрузка из 1С/WMS: CSV (разделитель «;» или «,») или JSON;
- _Демо-поток_ — имитация учётной системы: выдача на кладовые, приход, обмен баллонов.

Структуру ячеек (адреса, тип, размеры, места, нагрузка) можно выгрузить в учётную систему POST-запросом или CSV.

Срез — таблица, одна строка = ТМЦ (партия) в ячейке. Названия колонок сопоставляются в настройках:

| Поле                           | Значение                                                                       |
| ------------------------------ | ------------------------------------------------------------------------------ |
| `address`                      | адрес ячейки (обязательно)                                                     |
| `sku`, `name`, `group`, `unit` | артикул, наименование, группа, единица; новые позиции добавляются в справочник |
| `qty`, `weight`                | количество и общий вес строки, кг                                              |
| `batch`, `heat`, `cert`        | партия / серийный №, плавка, сертификат                                        |
| `expiry`                       | годен до (ЛКМ, ГСМ, химия)                                                     |
| `order`                        | заказ / строительный № (полуфабрикаты и изделия)                               |
| `tare`, `tareCount`            | код тары и количество; строка без артикула — пустая тара                       |
| `lastMove`                     | дата последнего движения                                                       |
| `fill`                         | заполненность 0..1 или %, если содержимое не передаётся                        |

```json
{
  "items": [
    { "address": "Ш1-01-01-01", "sku": "ЛС-D32-8", "qty": 10.7, "unit": "т", "heat": "Пл-24117", "weight": 10700 },
    { "address": "Б3-01-01-01", "sku": "ГАЗ-О2-40", "qty": 7, "tare": "Б40-О₂", "tareCount": 7 },
    { "address": "Т1-01-01-01", "tare": "EUR", "tareCount": 30 },
    { "address": "А1-01-01-01", "fill": 0.75 }
  ]
}
```

Адрес ячейки собирается по шаблону `{room} {zone} {rack} {section} {tier} {cell}` склада
(по умолчанию `{rack}-{section}-{tier}-{cell}`) и должен совпадать с адресом в учётной системе.
Нераспознанные адреса показываются при загрузке.

## Демо

При первом запуске создаются два объекта:

- **Центральный склад ТМЦ** судостроительного производства: двухэтажный корпус с мезонином, стеллажи паллетные,
  полочные и коробочные, консольные для труб и профиля, штабели листа, склад ЛВЖ, баллонная рампа
  с разделением кислорода и горючих газов, двор с металлопрокатом, навес, зона выдачи на кладовые цехов,
  полуфабрикаты (секции, фундаменты) и готовые изделия;
- **IT-склад (виртуальный)**: техника по местам учёта — склад, сотрудники, кабинеты, ремонт, подрядчики.

## Запуск

```bash
cd warehouse-3d
npm install
npm run dev          # http://localhost:5173
npm test             # юнит-тесты: ячейки, места, нагрузки, правила контроля, импорт среза
npm run build        # сборка в dist/
npm run build:single # всё приложение одним HTML-файлом в dist-single/
npm run mock-wms     # тестовая учётная система для проверки REST (http://localhost:8787)
```

Проверка REST: `npm run mock-wms`, затем в «Настройки → Учётная система → REST API» отправьте структуру
на `http://localhost:8787/api/locations`, укажите адрес API `http://localhost:8787/api/stock`, путь к массиву
`items` и получите срез.

Данные хранятся в браузере (IndexedDB). Перенос — «Настройки → Объекты → Выгрузить / Загрузить».

## Устройство

- `src/types.ts` — модель: склад → этажи → помещения → зоны → стеллажи / мезонины → ярусы → ячейки; срез остатков, партии, тара.
- `src/lib/rack.ts`, `src/lib/layout.ts` — геометрия стеллажей, расчёт ячеек и мест, генератор рядов.
- `src/lib/snapshot.ts` — разбор CSV/JSON, сопоставление полей, применение полного или частичного среза.
- `src/lib/monitor.ts`, `src/lib/control.ts` — заполнение, места, нагрузки секций и стеллажей, правила контроля.
- `src/lib/analytics.ts`, `src/lib/alerts.ts` — ряды для графиков, ABC, уведомления.
- `src/lib/connectors.tsx` — REST / WebSocket / файл / демо-поток.
- `src/lib/demo.ts`, `src/lib/demoData.ts`, `src/lib/catalog.ts` — демо-объекты, справочник ТМЦ и имитация учётной системы.
- `src/components/scene` — 3D (three.js, react-three-fiber): тысячи ячеек и грузов instanced-мешами, тени, этажи, мезонины.
- `src/components/plan` — 2D-редактор плана (SVG); `src/components/RackMap.tsx` — фасад стеллажа.
- `src/pages` — разделы приложения.
