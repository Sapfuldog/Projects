# Развёртывание «Склад 3D» в сети компании

Приложение запускается на одной машине в локальной сети и слушает все её сетевые интерфейсы (`0.0.0.0`).
Сотрудники открывают в браузере `http://<адрес-машины>:8080` — устанавливать на их компьютеры ничего не нужно.

Сервер (`server/server.mjs`, только Node.js, без сторонних пакетов):

- раздаёт собранное приложение;
- хранит **общую модель складов** — здания, этажи, зоны, стеллажи, ячейки, подключение к учётной системе,
  виды тары и кладовые. Её видят все; изменения одного сотрудника через несколько секунд появляются у остальных;
- проксирует запросы к учётной системе (1С, ERP, WMS): браузер обращается к `erp/…` на этом же сервере, без
  ошибок CORS, а логин и пароль учётной системы хранятся только на сервере.

Срезы остатков, справочник ТМЦ из учётной системы, выбранный склад и настройки вида у каждого пользователя
свои — в его браузере.

## Что нужно

- Машина в сети компании (Linux или Windows) с постоянным IP-адресом или DNS-именем — например,
  `sklad3d.zavod.local`; адрес выдаёт администратор сети.
- **Node.js 18 или новее** (рекомендуется 22 LTS) — или Docker.
- Открытый входящий порт (по умолчанию **8080**). Скрипты установки открывают его в брандмауэре сами.
- У сотрудников — Chrome, Edge, Firefox или Яндекс Браузер актуальной версии с включённым аппаратным
  ускорением (3D работает через WebGL). HTTPS не обязателен.

## Скачать без git

Репозиторий открытый: архив ветки скачивается по ссылке, git не нужен. В PowerShell в нужной папке:

```powershell
Invoke-WebRequest "https://github.com/Sapfuldog/Projects/archive/refs/heads/claude/warehouse-3d-map-mvm06a.zip" `
  -OutFile sklad-3d.zip -UseBasicParsing
Expand-Archive sklad-3d.zip -DestinationPath .
cd .\Projects-claude-warehouse-3d-map-mvm06a\warehouse-3d
```

Это исходный код: дальше нужен шаг `npm ci` и `npm run build` (см. ниже), для него нужен доступ к npm.
В PowerShell пишите `npm.cmd` вместо `npm` — иначе Windows с запретом сценариев не даст запустить `npm.ps1`.
Готовый пакет без сборки — `npm run release` (раздел «Сеть без интернета»).

## Быстрая проверка

```bash
npm ci
npm run build
npm start                 # слушает 0.0.0.0:8080
```

В консоли появятся адреса вида `http://192.168.1.20:8080` — откройте один из них на другом компьютере сети.
Остановка — Ctrl+C. Для постоянной работы выберите один из вариантов ниже.

## Вариант 1. Docker

```bash
cp sklad-3d.env.example .env      # порт, пароль редактора, учётная система — по желанию
docker compose up -d --build
```

- Порт публикуется на всех интерфейсах: `0.0.0.0:${PORT:-8080}`; другой порт — `PORT=80` в `.env`.
- Данные — в томе `sklad-data` (`/data` в контейнере), контейнер перезапускается сам.
- Журнал: `docker compose logs -f`; состояние: `docker compose ps` (проверка `/healthz` встроена в образ).
- Без доступа к Docker Hub и npm: укажите в `.env` образ Node.js и зеркало npm из внутренней сети:
  `NODE_IMAGE=registry.zavod.local/node:22-alpine`, `NPM_REGISTRY=https://nexus.zavod.local/repository/npm/`.
  Или возьмите готовый пакет (см. «Сеть без интернета»): в нём `Dockerfile` не собирает приложение, а только
  копирует готовые файлы, и npm не нужен.

## Вариант 2. Linux, служба systemd

```bash
npm ci && npm run build                 # или распакуйте готовый пакет, тогда сборка не нужна
sudo ./deploy/linux/install.sh          # порт 8080; другой: sudo ./deploy/linux/install.sh 80
```

Скрипт:

- создаёт системного пользователя `sklad3d`;
- копирует приложение в `/opt/sklad-3d`;
- создаёт настройки `/etc/sklad-3d.env` из `sklad-3d.env.example`;
- ставит и запускает службу `sklad-3d` с автозапуском;
- открывает порт в `ufw` или `firewalld`, если они включены;
- выводит адреса для сотрудников.

Данные — в `/var/lib/sklad-3d`. Порты ниже 1024 (например, 80) служба получает через
`CAP_NET_BIND_SERVICE`, без запуска от root.

```bash
systemctl status sklad-3d          # состояние
journalctl -u sklad-3d -f          # журнал
sudo systemctl restart sklad-3d    # после изменения /etc/sklad-3d.env
sudo ./deploy/linux/uninstall.sh   # удалить службу (данные и настройки остаются)
```

Служба работает в защищённом режиме: писать она может только в `/var/lib/sklad-3d`. Не меняйте `DATA_DIR` в
`/etc/sklad-3d.env` без правки `ReadWritePaths` в `/etc/systemd/system/sklad-3d.service`.

## Вариант 3. Windows

Установите Node.js LTS (или из пакета компании). Затем в PowerShell **от имени администратора** в папке
приложения:

```powershell
npm.cmd ci; npm.cmd run build  # не нужно, если это готовый пакет
powershell -ExecutionPolicy Bypass -File .\deploy\windows\install.ps1             # порт 8080
powershell -ExecutionPolicy Bypass -File .\deploy\windows\install.ps1 -Port 9000 -DataDir D:\Sklad3D
```

Скрипт:

- регистрирует задачу планировщика `Sklad3D`, которая стартует при включении компьютера от имени SYSTEM и
  перезапускается при сбое;
- добавляет правило брандмауэра «Склад 3D (TCP 8080)» для доменной и частной сети;
- создаёт `sklad-3d.env` рядом с приложением;
- выводит адреса для сотрудников.

Данные — в `%ProgramData%\Sklad3D`.

- Запустить вручную, без установки: `deploy\windows\start.cmd` — окно должно оставаться открытым.
- Удалить: `powershell -ExecutionPolicy Bypass -File .\deploy\windows\uninstall.ps1` (данные остаются).
- Если нужна именно служба Windows с перезапуском, заверните ту же команду
  (`node.exe server\server.mjs --host 0.0.0.0 --port 8080 --data C:\ProgramData\Sklad3D`)
  в NSSM или WinSW.

## Сеть без интернета

На любом компьютере с доступом к npm:

```bash
npm ci
npm run release        # → release/sklad-3d-<версия>/ и архив release/sklad-3d-<версия>.tar.gz
```

Перенесите архив на сервер и распакуйте (`tar -xzf …`; в Windows 10 и новее — тоже `tar -xzf` или любой
архиватор). В пакете:

- собранное приложение;
- сервер;
- скрипты установки;
- `Dockerfile` и `docker-compose.yml` для запуска без сборки.

На сервере нужен только Node.js — или Docker с образом Node.js. Дальше — вариант 1, 2 или 3; шаг
`npm ci && npm run build` пропускается.

## Настройки

Задаются в файле настроек:

- Linux-служба — `/etc/sklad-3d.env`;
- Windows и ручной запуск — `sklad-3d.env` рядом с `package.json`;
- Docker — `.env`.

Образец — `sklad-3d.env.example`. Вместо файла можно задать переменные окружения или ключи командной строки
(`--host`, `--port`, `--data`, `--erp-url`, `--edit-password`, `--env`). Ключи важнее переменных, переменные
важнее файла.

| Параметр                   | По умолчанию | Назначение                                                                        |
| -------------------------- | ------------ | --------------------------------------------------------------------------------- |
| `HOST`                     | `0.0.0.0`    | адрес для входящих подключений; `0.0.0.0` — все интерфейсы машины                 |
| `PORT`                     | `8080`       | порт                                                                              |
| `DATA_DIR`                 | `./data`     | общая модель (`model.json`) и резервные копии (`backups/`)                        |
| `EDIT_PASSWORD`            | —            | пароль на изменение складов; без него пользователи только смотрят                 |
| `ERP_URL`                  | —            | адрес учётной системы для прокси `erp/…`                                          |
| `ERP_USER`, `ERP_PASSWORD` | —            | вход в учётную систему (Basic)                                                    |
| `ERP_HEADERS`              | —            | другие заголовки, JSON: `{"Authorization":"Bearer …"}`                            |
| `ERP_CACHE_SEC`            | `5`          | сколько секунд один ответ учётной системы отдаётся всем — бережёт учётную систему |
| `BACKUPS`                  | `30`         | сколько резервных копий модели хранить                                            |
| `LOG`                      | `1`          | журнал изменений и ошибок в консоль; `0` — выключить                              |

Проверка работы: `http://<адрес>:8080/healthz` — отвечает `{"ok":true,…}` и номером версии модели.

## Общие данные и пароль редактора

- Первый, кто открыл приложение с пустого сервера, сохраняет на сервер свои склады — по умолчанию два
  демо-объекта. Дальше все видят одну модель.
- Если задан `EDIT_PASSWORD`, менять склады может только тот, кто ввёл пароль в «Настройки → Объекты →
  Сервер компании». Остальные смотрят: их правки не сохраняются, а в конструкторе висит пометка «Только
  просмотр». Пароль защищает от случайных правок; в сети без HTTPS это не защита от злоумышленника.
- Если двое правят одновременно, сохраняется изменение того, кто успел первым. Второй увидит сообщение и
  актуальную версию; свою правку он повторяет.
- Перенести склады, нарисованные раньше в браузере: «Настройки → Объекты → Выгрузить» в том браузере, затем
  «Загрузить из файла» в приложении с сервера.

### Резервные копии и восстановление

Перед каждой записью предыдущая версия модели сохраняется в `DATA_DIR/backups/model-<время>-v<версия>.json`;
хранятся последние `BACKUPS` копий. Чтобы откатиться:

1. Остановите сервер.
2. Скопируйте нужную копию поверх `DATA_DIR/model.json`.
3. Запустите сервер снова.

Для полного резервного копирования достаточно сохранять папку `DATA_DIR`:

- Docker: `docker run --rm -v warehouse-3d_sklad-data:/data -v "$PWD":/b alpine tar -czf /b/sklad-data.tgz -C /data .`;
  имя тома — в `docker volume ls`;
- Linux: `/var/lib/sklad-3d`;
- Windows: `%ProgramData%\Sklad3D`.

## Подключение учётной системы через сервер

1. В настройках сервера укажите `ERP_URL`, например `http://1c.zavod.local/base/hs/stock`, и при
   необходимости `ERP_USER` и `ERP_PASSWORD`. Перезапустите сервер.
2. В приложении: «Настройки → Учётная система → REST API», адрес — **`erp/items`**. Без `http://` и начального
   `/`, тогда адрес работает и за обратным прокси. Сервер отправит запрос на `ERP_URL/items`.
3. Выгрузка структуры ячеек в учётную систему — так же: `erp/locations`.

Прямой адрес учётной системы (`http://…`) тоже работает, если она разрешает запросы из браузера (CORS).
WebSocket-подключение идёт напрямую к учётной системе.

## Обновление

- Docker: `git pull && docker compose up -d --build`. Для готового пакета — распакуйте новый рядом, перенесите
  `.env` и выполните `docker compose up -d --build`. Данные в томе сохраняются.
- Linux: соберите или распакуйте новую версию и снова запустите `sudo ./deploy/linux/install.sh`.
  Настройки и данные сохраняются.
- Windows: замените папку приложения, сохранив `sklad-3d.env`, и снова запустите `install.ps1`.

У сотрудников достаточно обновить страницу. Файлы приложения кэшируются по хэшу, а сама страница
перепроверяется при каждом открытии.

## За обратным прокси (nginx) и HTTPS

Приложение работает и в подпапке: все его адреса относительные. Пример для `https://portal.zavod.local/sklad/`:

```nginx
location /sklad/ {
    proxy_pass http://127.0.0.1:8080/;
    proxy_set_header Host $host;
    client_max_body_size 50m;
}
```

В этом случае сервер «Склада 3D» можно слушать только на локальном адресе: `HOST=127.0.0.1`.

## Если не открывается

- **С сервера `http://localhost:8080` открывается, с других компьютеров — нет.** Закрыт порт в брандмауэре
  сервера или между сегментами сети: проверьте правило брандмауэра, спросите администратора сети. Сервер
  должен слушать `0.0.0.0` (в журнале при запуске: «Склад 3D слушает 0.0.0.0:8080»).
- **«Порт 8080 занят другой программой».** Укажите другой: `PORT=8081` или `--port 8081`.
- **«Нет сборки приложения».** Выполните `npm run build` — или используйте готовый пакет.
- **Вместо 3D — пустое место.** В браузере сотрудника выключено аппаратное ускорение или нет поддержки WebGL.
  Включите ускорение в настройках браузера; проверить можно на странице `chrome://gpu`.
- **Изменения не сохраняются.** Смотрите «Настройки → Объекты → Сервер компании»: «Нужен пароль редактора» —
  введите пароль; «Нет связи с сервером» — сервер недоступен, изменения отправятся, когда связь появится.
